# AGENTS.md

Internal tournament-management app for **Copa CD** — Apache Cordova (cordova-android 12.0.1), Windows-only workflow. No framework, no bundler, no tests. The app records teams, players, matchday results and standings for the Copa CD football tournament, following the rules of the official bases PDF (included as text, never as a PDF viewer).

## Commands

- Build APK: `.\build-reglamento.bat` → APK at `platforms\android\app\build\outputs\apk\debug\app-debug.apk`, log `build-reglamento.log`. Hardcodes `JAVA_HOME` (Adoptium JDK 17), sets `ANDROID_HOME` (`%LOCALAPPDATA%\Android\Sdk`), `GRADLE_USER_HOME` = kit offline (`..\mitienda-pos\build-offline\gradle-home`, `org.gradle.offline=true`). **No internet on this machine** — never clear that cache; default `~/.gradle` lacks AndroidX and hangs for tens of minutes.
- **`build-reglamento.bat` only runs Gradle — it does NOT copy `www/`.** After editing `www/` or `config.xml`, run `cordova prepare android` first (Cordova CLI 13, global), then the .bat. **The prepare must run with the working directory = this project root**: once it was invoked from another sibling project and silently prepared THAT one (exit 0, no output), leaving `platforms\...\assets\www\index.html` stale and the APK outdated — always verify the APK's `assets/www/index.html` SHA against the source after a build. **Sin Cordova CLI** (máquina de Luis): el .bat apunta a una ruta inexistente; copiar a mano `www/index.html` → `platforms\android\app\src\main\assets\www\index.html` y compilar con `platforms\android\gradlew.bat --offline --console=plain cdvBuildDebug` (workdir `platforms\android`) con `JAVA_HOME` (Adoptium 17) y `ANDROID_HOME=%LOCALAPPDATA%\Android\Sdk`; usa el `~\.gradle` de Luis, que ya trae Gradle 8.0.2 + AndroidX/AGP. Verificar el APK: `assets\www\index.html` SHA == fuente, `assets/www/plugins/cdp-compartir/www/cdpcompartir.js`, `res\xml\cdp_file_paths.xml` y `aapt dump xmltree <apk> AndroidManifest.xml` con `cdpfiles`.
- Versions come from `config.xml` preferences (Gradle 8.0.2, AGP 8.0.0, Kotlin 1.8.20, **SDK/compileSdk/targetSdk 34 · build-tools 34.0.0**). Pinned to the kit's Maven cache — don't bump them **except** SDK/build-tools: en la máquina de Luis `build-tools\33.0.2` y `platforms\android-33` están **vacíos** (solo `.installer`) y no hay Cordova CLI, así que se subió a 34.0.0/34 (AGP 8.0.0 los acepta) y se parcheó **a mano** `platforms\android\cdv-gradle-config.json` (`SDK_VERSION`/`COMPILE_SDK_VERSION`/`BUILD_TOOLS_VERSION`), porque sin `cordova prepare` ese JSON generado no se regenera desde `config.xml`.
- No tests/lint/typecheck. Offline smoke test that works well: extract the inline `<script>` and run `node --check`, then render `www/index.html` plus an injected click-script with Edge headless and inspect the dumped DOM. Gotchas proven in practice: (a) PowerShell `>` and `msedge --headless=new` gave an empty dump — use `--headless=old` launched from a `.bat` (`%TEMP%\opencode\smoke.bat`); **`--virtual-time-budget` must be 300000** — at 60000 the budget expires before the current run finishes and the dump comes back with no `#smoke-result` at all; (b) `document.innerText` is empty/unreliable in that dump — assert on `textContent` of `#app` (never `document.body.textContent`, it includes the script source and makes checks pass trivially); (c) goal chips (`[data-a="mk"]`) only exist once a team has players — add some first; dispatch `pointerdown`+`pointerup` events, not `click`; (d) the match overlay `#partido` lives OUTSIDE `#app` — assert its content via its own `textContent`, not `T()`; (e) the test overrides `window.confirm`/`prompt` with a counter (`window.__cf`/`window.__cfR`, headless dismisses dialogs — set `__cfR=false` to simulate Cancel); (f) the app script is an IIFE so nothing is global — the smoke uses the `window.__app` hook (`{cargar,render,crearTorneo,faltantes,jornada,atras,sortearTodo,vista,partidoAbierto,navReset,aplicarSync,sincronizarTexto,paqueteSync,b64enc,b64dec,puedeEq,idCopa,capitanesDe,cerrarSync,estado,usuarioActual,esAdmin,pueArb,abrir,slugUsuario}`) for direct calls — sync must be exercised through these calls, never by clicking the UI buttons (they `alert()` and headless deadlocks); (g) regexes written inside the smoke template literal lose their backslashes (identity escapes in cooked templates) — use `indexOf` or write `\\d` in the generator; (h) the bombo/cards flow runs before the match opens, so the smoke draws one card through the UI (`carta-sacar` → optional `carta-elegir` for comodines → `carta-cerrar`) and fills the rest with `__app.sortearTodo()`; (i) the back button is simulated with `document.dispatchEvent(new Event('backbutton'))` (no cordova.js in the browser); (j) the smoke is regenerated by `%TEMP%\opencode\crear-smoke.js` into **`www/smoke.html` — DELETE it before `cordova prepare`** or it ships inside the APK; (k) session flow mirrors real usage: `luis` (superadmin) creates and manages everything, `manu` (segundo superadmin fijo) entra/sale una vez para validar el login, `carlos` (capitán) logs in/out to assert the per-team restrictions, then back to `luis` for archivar. **How to run**: `node %TEMP%\opencode\crear-smoke.js` (rewrites `www\smoke.html` from the current `index.html`) → `%TEMP%\opencode\smoke.bat` → read `%TEMP%\opencode\smoke-out.html` and take the **last** `SMOKE|…` occurrence (or the `#smoke-result` element) — the generator's own template literal is also in the dumped DOM and matches `SMOKE|` first. Required result: `TODO-OK` with zero `FAIL:`/`EXCEPCION:`; check totals drift as the app grows, so no recorded count is authoritative.
- `npm install` only works if `..\mitienda-pos` exists (`cordova-android` is `file:../mitienda-pos/node_modules/cordova-android`, junction, v12.0.1).
- **Plugins locales Android**: `cdp-compartir` comparte un fichero `.json` real con FileProvider y, al iniciar, limpia `files/cdp-voz` de una versión anterior para liberar el modelo sin borrar los datos del torneo. Los avisos temporizados usan el tono Web Audio de `beepAlerta()`; no se incluye sintetizador de voz offline ni dependencias TTS.

## Architecture

- The whole app is one file: `www/index.html` (inline `<style>` + inline `<script>`, single `<script>` tag, state in `localStorage` key `mtp_copa_cd`). `www/` holds only `index.html`, `assets/` and the generated `smoke.html` — nothing else to wire up.
- Views (7 pestañas + `asistente` + bases): `dashboard`, `jornada`, `tabla`, `jugadores`, `fairplay`, `historial`, `equipos`, más `usuarios` (solo super admin) y `asistente` (IA, todos los roles); las bases se abren desde el botón 📖 de la cabecera (con `data-a="volver"` a `S.ui.anterior`), no desde la nav. La nav se genera en `render()` desde `PESTANYAS` filtrando por rol — no la edites como HTML fijo. **La nav es un drawer lateral izquierdo**: `#nav` (`position:fixed; left:0`, `transform:translateX(-105%)`, se muestra con la clase `.abierto`), botón ☰ `#nav-btn` **dentro de la cabecera `.cab`, antes del logo** (32×32, **sin fondo rojo** — `background:none;border:none`, solo el ☰ blanco con `text-shadow` hairline para verse sobre la cabecera clara `#fff`, `display:none` hasta haber sesión; al quedar dentro de `.cab` z5 queda por debajo del drawer z40: con el menú abierto se cierra por tap fuera/back, no tocándolo) que conmuta la var runtime `navAbierto`; se cierra en `irA()`, **lo primero** en `atras()`, por tap fuera (`closest('#nav,#nav-btn')`), en `salir`, en `navReset()` y en la rama sin sesión de `render()`. Queda **intencionalmente por debajo** de `#partido` (z50) y `#carga` (z60). La nav tiene **cabecera premium** `.nav-hd` (logo + «COPA CD» + rol/usuario) y `.nav-lbl`; los items (`<b>` icono + texto) entran animados con `@keyframes navIn` (retardo escalonado por `animation-delay` inline) y el activo lleva `.on` con gradiente rojo. El chip de capitanes se muestra a **todos los roles** (admins incluidos, con hint «pulsa 👑 …» si está vacío) y muestra `© Capitán:` / `© Capitanes:` — el plural se escribe completo (`'Capitán'+'es'` daba «Capitánes», acento mal puesto). **Dashboard es la primera pantalla**: `vistaPorDefecto()` devuelve `dashboard` para todos los roles (login, logout y guardia de rol caen ahí). Su diseño: hero con degradado (`.dash-hero`, barra de progreso de la jornada + CTA «Ir a la Jornada») en las variables nuevas `--hero1/--hero2/--hero-s/--hero-cta` — rojo→granate en claro (`#F52B27→#8C1614`), casi negro en oscuro (`#070708→#151517`), **el navy `#14306B` ya no aparece en el hero**; fila `.dash-sync` con «📤 Compartir copa»/«🔄 Sincronizar» + la nota «ID de la copa»; **6 tiles** (`.dash-tiles`: 🏁 partidos jugados, 🎴 cartas, 👥 jugadores activos, ⚽ goles totales, 🚫 fuera de la copa, 🏆 copas archivadas); bloque `.dash-sec` «⚽ Próximo partido · Jornada N» (CTA `data-a="abrir"`, solo si `!fal.length&&S.jornadas.length` — **la condición es `!fal.length`, ojo: `!fal` sobre un array es siempre false y la sección nunca se renderiza**); «🕐 Últimos resultados» (últimos 5, más reciente arriba); «⚽ Top goleadores» y «⚖️ Top fair play» con 🥇🥈🥉 (`.dash-top`, reemplazan a `.lideres`); mini-clasificación con medallas 🥇🥈🥉 (`.dash-pod`). **Los textos que el smoke valida no se pueden renombrar**: `Jornada N en curso`, `Ir a la Jornada`, `N / 12`, `Clasificación`, `La jornada no puede empezar`, `Faltan N`, `Bienvenido a Copa CD`, `El torneo aún no está creado`, `Partidos jugados`, `Cartas del bombo`, `Jugadores activos`, `Goles totales`, `Fuera de la copa`, `Próximo partido`, `Últimos resultados`, `ID de la copa`, `Jornada N de 4`, `N / 12 partidos registrados`.
- Puerta de entrada a Jornada: `faltantes()`/`torneoListo()` exigen **≥5 jugadores activos por equipo**; `vistaJornada()` renderiza el panel de bloqueo con el detalle por equipo en vez de los partidos si no se cumple. Además `jornadaActual()` = primera jornada con algún partido `pendiente`; en la nav de jornadas solo se puede JUGAR la actual (chips `J1..J4` en una sola fila — `.chips`/`.chip` `nowrap` con `flex:1`; futuros con 🔒 `.locked` y guardia en el caso `jor`; las anteriores se ven en modo lectura).
- Partido a pantalla completa: `S.ui.partido` abre el overlay `#partido` (fuera de `#app`, renderizado por `renderPartido()` en cada `render()`); solo hay un partido posible a la vez porque el overlay cubre la nav. Incluye cronómetro (`cron` runtime en memoria, no persistido: `mins/seg/corriendo/t`, cuenta atrás configurable 1-120 min, Iniciar/Pausar/Reiniciar) y botones FF/nulo/limpiar. **`estado:'jugado'` SOLO se pone en `terminarPartido()`** — se quitó el auto-flip en `ajustarPor` (marcar goles ya no cierra el partido; cerrar sin terminar lo deja `pendiente` con confirm). Al terminar, `S.ui.jor` salta a `jornadaActual()`. Los partidos `jugado` se reabren en modo revisión (solo Cerrar); FF/nulo no se abren. **Estadísticas bloqueadas hasta ▶ Iniciar**: `p.iniciado` (flag persistido, se pone en `cronIniciar`, se resetea en `est`/`limpiar`) — sin él, los chips salen con clase `.mk.off`, `ajustarPor` hace toast y «⏹ Terminar» no aparece; FF/nulo/limpiar/duración/cronómetro sí están siempre permitidos.
- **Capitán y co-capitán (2026-11)**: cada equipo tiene **un capitán y un co-capitán** en `equipos[i].capitanes[]` — índice 0 = capitán, índice 1 = co-capitán (`capitanDe(e)`/`cocapitanDe(e)`, `normalizarCapitanes(e)` deja el array sin huecos). **Cambiar de capitán** (super admin): botón «👑 Cambiar capitán / Asignar capitán» en `capPanelEq` (`data-a="cap-pick"`, se ve al instante en Equipos) y el 👑 de la fila del jugador (un toque sobre un jugador que no es capitán también lo cambia). Ambos pasan por `hacerCapitan(e,j)`: crea/actualiza su usuario con `crearUsuarioDeCapitan` (slug de `slugUsuario(nombre)`), lo pone en el slot 0, **manda al capitán saliente al slot 1 (co-capitán)** si ese hueco está libre — si ya había co-capitán, el saliente deja el puesto y el co-capitán se mantiene —, limpia `partido.arbitro` del capitán saliente (`limpiarArbitrajesDe`), `reasignarArbitrosPendientes()`, `S.capTs=Date.now()` y `guardar();render()`. El 👑 sobre el capitán actual lo **retira** (sube al co-capitán o deja el equipo sin capitán y borra su usuario). El selector es el mismo modal `#cocap` con `cocapUI={eq,modo:'cap'}` y `renderCocap()` en dos modos (`cap`/`co`), y solo se pinta en la vista `equipos`; lista los jugadores activos menos el capitán actual y avisa quién baja de puesto. El 🎖 designa/quita co-capitán: `puedeCambiarCoCap(e)` = super admin **o** el capitán real de ese equipo (el co-capitán no puede). El modal `#cocap` (`data-a="cocapitan"`, `cocap-set`/`cocap-cerrar`) lista los jugadores activos del equipo menos el capitán. El co-capitán **también tiene usuario**: `hacerCoCapitan(e,j)` (usado por `cocap-set`) asigna el slot 1 y llama a `crearUsuarioDeCocapitan(e,nom)` → `crearUsuarioDirEquipo(e,nom,true,permDirEquipo(e))`, que crea el usuario `r:'capitan'`, `equipo` igual, contraseña inicial `copa1234`, `debeCambiar=true`, `co=true` y **permisos clonados del capitán** (`permDirEquipo`/`sincronizarPermisosDir`). Al quitar/cambiar de co-capitán se elimina su usuario (`quitarUsuarioCoCapitan`) y al cambiar de capitán se conserva al co-capitán anterior y se limpia al capitán saliente. `usuarioCoCapitanDe(e)` resuelve el username del slot 1. La única diferencia de permisos es que **no puede cambiar de capitán**: `hacerCapitan`/`cap-set` siguen exigiendo `esAdmin()`. El co-capitán **no arbitra** (`capitanesEquipo()` solo devuelve capitanes). En Usuarios el badge distingue CAPITÁN/CO-CAPITÁN con `rolCapUsuario(e,u)`.
- **Árbitro por partido (2026-11)**: solo arbitran **los 4 capitanes** y **nunca un partido de su propio equipo**. `partido.arbitro` guarda el **username** del capitán designado (`''` = solo super admin). `asignarArbitros(J, respetar)` reparte los 12 partidos entre los capitanes elegibles equilibrando el uso (`reasignarArbitrosPendientes()` tras generar/borrar/importar); el legado `jornada.arbitro` se migra a `partido.arbitro` en `cargar()` y `jornadaArbitro(n)` queda como fallback. `vistaJornada` pinta el panel «🧑‍⚖️ Árbitros de la Jornada N» con chips de uso por capitán, botón «Repartir entre los capitanes» (`arb-repartir`) y, para `puede('torneo')`, un `select data-i="p-arb"` por partido; los demás ven el nombre en solo lectura. En el partido se abre el modal `#arb` (`data-a="arb-pick"`, `renderArb()`, `arb-set`/`arb-cerrar`) que solo ofrece capitanes de equipos que no juegan ese partido. `puedeArbitrar(pid)` (= `esAdmin()` o (`puede('jugar')` y `partido.arbitro===S.sesion.u`)) gatea: `abrirPartido` sigue dejando abrir para consultar, pero `renderPartido` oculta cronómetro/Iniciar/FF/nulo/limpiar, muestra «modo lectura» y la cabecera indica «Árbitro: … · tú pitás este partido»; los chips salen `.mk.off`; `ajustarPor`, `est`, `limpiar`, `pt-iniciar/pausar/reset/terminar` y `carta-sacar/elegir` hacen toast y no actúan. El bombo muestra 🔒 con el nombre del árbitro en vez de «Sacar carta». `jug-del`, `jug-fuera`, `user-del` y el cambio de capitán limpian `partido.arbitro` y re-reparten. La nube (**`sanearPaqueteNube`**) borra `partido.arbitro` y `mezclar()` solo lo rellena si el local lo tiene vacío.
- **Sanciones por equipo (2026-11)**: el capitán tiene `perm.sanciones`, pero solo puede añadir/quitar sanciones de **su propio equipo** (`puedeSancionarEq(id)`/`equiposSancionables()`); el formulario `#sanc-form` solo lista esos equipos y muestra el candado; **el co-capitán sí sanciona** de su equipo (`puedeSancionarEq` acepta `usuarioCapitanDe(e)` o `usuarioCoCapitanDe(e)`), como parte de los permisos copiados del capitán. El super admin sigue viendo los 4.
- **Puertas por jornada (2026-11)**: cada jornada las puertas las lleva **un puesto distinto de la tabla**: J1 el **cuarto (último)**, J2 el **tercero**, J3 el **segundo**, J4 el **primero** — `PUERTAS_PUESTO=[4,3,2,1]` (índice 0 = J1). Como al empezar **no hay copa ni clasificación**, el orden de lugares se elige **a mano** en `S.ordenLugares` (array de ids, posición 0 = 1º); `crearTorneo()` lo siembra `[1,2,3,4]`, `cargar()` lo migra y **`normalizarOrden()`** lo deja en una permutación de los 4 equipos (dedupe + relleno). Helpers: `puestoDe(id)` (1-4), `puertasDe(n)` (equipo que lleva las puertas de la jornada n), `puestoPuertasEtiqueta(n)` («último lugar»/«tercer lugar»/«segundo lugar»/«primer lugar»), `tablaOrdenada()` (ids según `calculo()`). UI: tarjeta «🚪 Puertas · lugares de la copa» (`panelPuertas()`) en **Equipos** con 4 `select data-i="orden" data-pos=i` — cambiar un lugar **intercambia** posiciones (nunca duplica) —, chips `J1..J4 · equipo` y botón **«📊 Usar la clasificación actual»** (`orden-tabla`, rechaza con toast si aún no hay partidos jugados); tarjeta `.pue-card` «Puertas de la Jornada N» en Jornada; línea `🚪 Puertas JN: equipo (puesto)` en el hero del dashboard. Sync: `paqueteSync` incluye `ordenLugares`, la adopción de dispositivo vacío lo copia y `mezclar()` solo lo **rellena si el local está vacío** (el local manda). Solo `puede('torneo')` edita los lugares (el resto en solo lectura).
- **Capa visual moderna (2026-11)**: bloque CSS grande al final de `<style>` (tokens Material-3, ripple, sombras, `navIn`/`cardIn`/`bnavIn`) + **login de cristal a pantalla completa** (`vistaLogin`/`vistaCambiarPass`: `.login-bg` con orbes y rejilla, `.lg-ring` con el escudo, campos con etiqueta flotante y ojo `data-a="pass-ojo"` que alterna `type`). `render()` pone `body.en-login` (sin sesión **o** con `sesion.debeCambiar`) y oculta `.cab`/`#sesion`/`#bnav` para que el cristal ocupe toda la pantalla. **Barra inferior `#bnav`**: `barraInferior(r)` pinta las 4 primeras pestañas permitidas y no bloqueadas + botón «Menú» (que duplica el ☰ del drawer); se oculta sin sesión y `body` reserva su alto con `--bnav-h`. Los modales `#cocap` y `#arb` van en `z-index:72` (por encima de `#partido` 50 y `#carga` 60); `#bnav` es 35 y el drawer 40.
- **Bombo de cartas (las 14 cartas oficiales, array `CARTAS` tras `MOTIVOS`)**: cada jornada tiene su mazo persistido `S.jornadas[i].bombo={mazo:[1..14 barajados],pos}` — `sacarCarta()` consume en orden y **al agotarse re-baraja** (regla «se vuelven a sacar»); `cartasFaltantes(J)` cuenta partidos sin carta. La jornada **no arranca sin sus 12 cartas**: `vistaJornada` muestra el panel «🎴 Bombo de cartas» con un botón «Sacar» por partido (modal con animación de volteo `#carta` + `renderCarta()`; los comodines 5/6 abren selector `carta-elegir` de dinámica), y `abrirPartido` rechaza partidos pendientes con toast si faltan. Asignación: `p.carta`, comodines además `p.comodin` (equipo) y `p.comodinDe`. Badge 🎴 en `htmlPartido`, banner con regla/observaciones en `renderPartido`. `minutosPartido(p)` fija 10 minutos o 15 si es carta 14, más los 2 del challenge ganado. El botón «⟲ Reiniciar copa desde cero» está en el Dashboard para el super admin; desde Jornada se puede usar «↺ Reiniciar jornada N» en cualquier jornada seleccionada, incluso una ya terminada; el reinicio de una jornada limpia solo sus partidos, cartas, challenge y sanciones, y deja intactas las demás jornadas. El reinicio total conserva Histórico, usuarios, sesión y tema, y elimina los datos de la copa activa. **Gol doble (carta 7) automático**: al marcar gol se estampa `min` con `floor(segundos/60)` (0:00–0:59 → 0, …, 4:00–4:59 → 4, 5:00–5:59 → 5); solo goles con **`min<5`** cuentan **dos para el equipo y el marcador** (`mar(p)` y la tabla), mientras `calcEstadisticas()` conserva **un gol para el jugador**. Ojo: era `<=5` y duplicaba también los goles entre 5:00 y 5:59 (6 goles → 12 en vez de 8). A los 5 minutos, cartas 7 y 2 emiten un tono y aviso visual («Terminó el gol doble» / «Comienza 3 para 3…»). **Juego limpio (carta 11)**: el aviso lista los jugadores con amarilla en partidos ya jugados de esa jornada y sus chips se bloquean; `ajustarPor()` también impide registrarles estadísticas en ese partido. **Aplicar/No aplicar (cartas 8-11)**: `panelReglasCarta(p,puedeEditar)` pinta ✅ Aplicar / ❌ No aplicar en el overlay; el estado vive en `p.aplica[id]` (por defecto `true`, `reglaAplicada()`), se graba con `data-a="regla-set"` y se limpia al sacar/reelegir cada carta. Con «No aplicar» se omite el aviso de cambios obligatorios (8), se libera a los jugadores con amarilla previa (11) y se muestra «Regla NO aplicada · juego normal»; el marcador y las estadísticas cuentan igual. En la lista de partidos aparece el badge «Regla no aplicada». Solo quien puede arbitrar y editar la jornada cambia el interruptor. `sortearTodo()` (hook del smoke) rellena todo de una vez.
- **Atrás y gestos**: `cordova.js` real (63.747 bytes, copiado de `..\mitienda-pos\platforms\android\platform_www\cordova.js` — la plantilla compartida en `node_modules/cordova-android\templates\...\cordova.js` está a **0 bytes** y el plugin JS no arranca sin él; `platform_www` lo conserva entre prepares, pero al ser `platforms/` generado, si se regenera la plataforma hay que volver a copiarlo). `index.html` lo carga con `<script src="cordova.js">` antes del script inline (en navegador da 404 inofensivo). cordova.js auto-activa `overrideBackbutton` al registrar el listener `backbutton`. ## Reglamento rules (the main footgun)

The app must stay byte-consistent with the official bases (text embedded from the PDF, section `#bases-brutas`, rendered by `vistaBases()`). Non-negotiable numbers:

- 4 equipos · 4 jornadas · 12 partidos/jornada (each of the 6 pairings **twice**) · 10 min con 2 botes · domingos 5:00 pm Ciudad Deportiva.
- Cronograma fijo (en `CRONOGRAMA`, equipos por orden de creación, ids 1-4): J1 `1-2 3-4 1-3 2-4 1-4 2-3`, J2 `2-3 1-4 2-4 1-3 2-1 3-4`, J3 `3-4 2-1 3-1 4-2 3-2 4-1`, J4 `4-1 2-3 4-2 3-1 4-3 1-2`.
- Puntos 3/1/0; desempate: diferencia de goles → partidos entre ellos → penales.
- FF: partido 3-0, se borran las estadísticas (goles/tarjetas/paradas) pero los puntos sí se otorgan y GF/GC **no** se computan; cada FF suma 4 cervezas al premio final.
- Ambos con 2 jugadores = partido nulo (nadie puntúa, estadísticas fuera).
- Sanciones -3 por jornada (puertas/campo, planillas, anotador oficial, indumentaria indebida, 400 pesos, último lugar sin estadísticas) — se descuentan en la tabla vía `jornadas[].sanciones`.
- 8 jugadores por equipo (5+3); la app exige **≥5 jugadores activos por equipo para abrir la Jornada** y permite **máx. 3 sustituciones por copa** (`j.fuera` + `e.cambios`); 3 amarillas = pierde el próximo; roja = expulsado de ese partido y el siguiente (badge informativo en la tabla de jugadores).

## Firebase cloud exchange

`www/index.html` has an optional manual cloud exchange over Firebase Authentication (Email/Password) and Realtime Database REST. Every logged-in app role can use the cloud exchange; the existing `sync` permission still gates manual file/code exchange and file sharing. Each app installation keeps its latest snapshot at `copas/<idCopa>/paquetes/<uid>/dispositivos/<deviceId>`; downloading reads the copa's device snapshots and merges them using `aplicarSync()` (same cup ID, local data wins). Cloud snapshots omit photos and local APK accounts/passwords/captain references. Firebase Web API key and RTDB URL are configured per device in the sync modal; Firebase auth tokens stay in memory. Once signed in, the sync modal offers **🔁 Auto**: with it enabled, `guardar()` debounces `nubePublicar(true)` (900 ms) so captain/player/referee changes upload automatically, and a 45 s poll calls `nubeDescargar(true)`; if another device contributed data, a toast says «Otro dispositivo actualizó la copa». The auto flag is per-device (`mtp_copa_cd_nube_auto`), is not included in `paqueteSync`, and stops on logout/config change; tokens are still in memory, so the user signs in to Firebase on each app start. `nubeBatch` suppresses publishes while downloading/merging, avoiding loops. Internet is required for cloud exchange; file/code sync (WhatsApp, Zapya, Bluetooth, Nearby Share) continues to work offline and remains the only option without internet — true realtime without any network is not possible between two standalone APK installs.

Firebase project setup: enable Email/Password in Authentication, create a Realtime Database, and install these rules. Any authenticated Firebase account that knows a cup ID can read its snapshots and publish its own device snapshot, so this is a shared exchange, not private storage; do not put sensitive data in the tournament.

```json
{
  "rules": {
    "copas": {
      "$idCopa": {
        "paquetes": {
          ".read": "auth != null",
          "$uid": {
            "dispositivos": {
              "$dispositivo": {
                ".write": "auth != null && auth.uid === $uid && newData.exists()",
                ".validate": "newData.hasChildren(['createdAt', 'uid', 'paquete']) && newData.child('uid').val() === $uid && newData.child('paquete').child('app').val() === 'copacd' && newData.child('paquete').child('idCopa').val() === $idCopa && !newData.child('paquete').child('datos').child('usuarios').exists()",
                "createdAt": { ".validate": "newData.isNumber()" },
                "uid": { ".validate": "newData.isString()" },
                "paquete": { ".validate": "newData.hasChildren(['app', 'idCopa', 'datos'])" }
              }
            }
          }
        }
      }
    }
  }
}
```

Firebase Storage **ya no se usa**: las actualizaciones de la APK van por GitHub Releases (ver apartado siguiente).

## Actualización de la APK (GitHub Releases) y anotaciones multi-móvil (2026-11)

`APP_VERSION`/`APP_BUILD` viven al inicio del `<script>` de `www/index.html` (hoy `1.0.3`/`4`).
